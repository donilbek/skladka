# Складка

Архиватор файлов и папок для браузера и Windows. Данные сжимаются на устройстве. При распаковке «Складка» проверяет SHA-256 и восстанавливает имена файлов и структуру папок.

## В браузере

Скачайте `index.html` и откройте его в браузере. Выберите файл или перетащите папку в окно, затем сохраните архив `.skl`. Чтобы восстановить данные, выберите **Распаковать**. Для публикации сайта разместите `index.html` на статическом хостинге.

## На Windows

Скачайте и запустите `Skladka.exe`. Установка и API-ключ не требуются. Для архива папки приложение предложит выбрать каталог для сохранения.

## HTTP API

Для запуска сервиса установите ASP.NET Core Runtime, указанный в `server/Skladka.Api.runtimeconfig.json`. Из корня репозитория выполните

```sh
dotnet server/Skladka.Api.dll
```

По умолчанию сервис доступен на `http://127.0.0.1:8787`. Метод `GET /v1/health` проверяет доступность. Для сжатия отправьте исходные байты на `POST /v1/compress`, для распаковки отправьте архив на `POST /v1/decompress`. Используйте тип содержимого `application/octet-stream`.

## Исходный код и сборка

| Папка | Содержимое |
| --- | --- |
| `src/` | Кодек, обработка папок и интерфейс для Windows |
| `api/` | Проект HTTP-сервиса |
| `web/` | Интерфейс браузера, кодек и сценарий сборки автономной страницы |
| `tests/` | Проверки API, распаковки и потокового SHA-256 |

Для сборки Windows-приложения запустите `build.cmd` на 64-разрядной Windows с .NET Framework 4.8. Результат появится в корне как `Skladka.exe`.

Для сборки сайта выполните `python web/build.py`. Готовая автономная страница появится в `web/dist/index.html`. Для запуска API из исходников выполните `dotnet run --project api -c Release` с установленным .NET SDK 10.

## Алгоритм


* **Границы блока.** В пределах 512 КиБ кодек анализирует окна по 32 КиБ. В каждом окне он оценивает энтропию Шеннона по серии разнесённых выборок байтов. Если оценка отличается от первого окна блока более чем на 0,8 бита на байт, начинается новый блок. Последний блок может быть короче 32 КиБ. Если анализ предложил разбиение, кодек пробует и весь участок целиком. Сравнивается общая длина записей вместе с заголовками.
* **Выбор представления.** Однородный блок кодируется одним байтом значения. Для остальных сравниваются исходные байты, Deflate и словарное кодирование. Энтропия исходных и преобразованных данных помогает решить, какие дополнительные комбинации проверить. При оценке ниже 7,7 бита на байт кодек пробует соответствующую ветвь. Из фактически проверенных вариантов выбирается кратчайший.
* **Delta.** Выбирается шаг 1, 2, 4 или 8 байт по ошибке на выборке. Разности по модулю 256 кодируются Deflate и собственным словарём. Сравниваются оба размера.
* **Перестановка.** Каждая из четырёх байтовых позиций записи собирается в отдельную последовательность, затем последовательности сжимаются вместе с помощью Deflate. Поддерживаются неполные записи.
* **Межблочный словарь.** Словарный кодер видит последние 65 535 исходных байтов файла перед текущим блоком. Хеш трёх байтов даёт позицию кандидата. Совпадения длиной 4–130 байт заменяются обратными ссылками, остальные байты объединяются в буквальные серии. Декодер восстанавливает историю только из уже распакованных данных этого архива.
* **Контекстный предиктор.** Для каждой пары предыдущих байтов таблица запоминает последний байт, следовавший за этой парой. Для новой пары предсказание продолжает последнюю разность. Ошибки предсказания по модулю 256 сжимаются Deflate. Декодер обучает таблицу на восстановленных байтах в том же порядке.

### Кодирование похожих фрагментов

Для позиции в блоке кодек находит два последних кандидата по хешу четырёх байтов. Ещё один кандидат задаётся расстоянием предыдущей выбранной ссылки. Предшествующие 65 535 байт доступны как начальный словарь, внутри блока можно сослаться и дальше. При точном совпадении первых четырёх байтов кодек продолжает сравнение до 65 536 байт. За совпадение начисляется 1 балл, за расхождение вычитается 5. Выбирается префикс с наибольшим баллом выше 9. Поиск завершается при отставании от локального максимума более чем на 24 балла или после 64 байт без нового максимума.

Поток состоит из буквальных серий и ссылок с поправками. Целые поля записываются семибитными группами от младших к старшим, старший бит означает продолжение. Чётный тег равен удвоенной длине буквальной серии. За ним идут байты серии. Нечётный тег равен удвоенной длине ссылки плюс один. Далее идут расстояние назад, число поправок и пары из пропуска и ненулевой XOR-разности. Пропуск отсчитывается от начала ссылки либо сразу после предыдущей поправки. Копирование идёт слева направо. Каждая поправка применяется сразу, чтобы перекрывающиеся ссылки могли использовать исправленные байты.

Метод 70 хранит собственный поток команд как есть. Метод 71 предваряет его Deflate-представление четырёхбайтовой длиной потока команд. Выбор учитывает эти четыре байта. Кодек сравнивает их размер с остальными представлениями блока. Кодек проверяет размеры, расстояния и границы поправок до выдачи результата. Оригинальная часть реализации — поиск образца, правила выбора длины и представление исправлений. Обратные ссылки, XOR и Deflate относятся к известным техникам сжатия.

### Формат папки

Перед сжатием дерево записывается в один поток. Каждая запись содержит тип (0 — каталог, 1 — файл), длину пути в UTF-8 (2 байта little-endian) и путь относительно родителя корневой папки. Разделитель — `/`. После пути файла записаны 8-байтовый размер в little-endian и содержимое. Первая запись обозначает корневую папку, каждый каталог записывается до его детей. У пустой папки есть собственная запись, у пустого файла — запись с нулевой длиной. Весь поток сжимается тем же кодеком, что и одиночный файл. Заголовок папки использует 64-битную длину потока. Проверка SHA-256 охватывает и пути, и данные. Распаковщик проверяет структуру, имена, отсутствие дубликатов и границы данных перед сохранением.

### Формат файла

Заголовок хранит сигнатуру SKLD, версию, размер файла и имя UTF-8. В зависимости от размера файла для длины используется 32-битное или 64-битное поле. В обоих форматах каждый блок содержит исходную длину (4 байта), метод (1 байт), длину полезной нагрузки (4 байта) и саму нагрузку. Многобайтовые числа записываются в little-endian. Методы 0, 1, 2 и 3 обозначают исходные байты, одинаковые байты, локальный словарь и Deflate. Методы 16+шаг и 32+шаг обозначают Delta с Deflate и словарём соответственно. Методы 64, 65 и 66 обозначают словарь с историей, перестановку с Deflate и предиктор с Deflate. Завершает архив SHA-256 исходного файла.

## Проверки

```sh
python tests/check_api.py --large
node tests/check_hash.cjs
```

Первый тест собирает сервис, сжимает файлы, перезапускает процесс и сверяет SHA-256 после распаковки. Второй сравнивает потоковое хеширование в браузерном кодеке с эталонной реализацией Node.js.
